# Changelog

All notable changes to Arnotes are documented in this file.

## Unreleased

- Two-factor settings ask for your password in a dialog (Set up, Add another app, New backup codes, Turn off); a wrong password keeps the dialog open. "Add another app" shows the key again so you can scan it in more authenticator apps, such as Google Authenticator, Dashlane or Bitwarden: every app holding the key shows the same codes
- Maintenance mode for deploys. While `MAINTENANCE_MODE` is on, or the file `maintenance.on` exists (no restart needed), every request gets a 503 with Retry-After: a small self-refreshing page in the browser, JSON for the API and the agent endpoint. `/api/health` stays up, and due-date rules pause
- A project has a Settings page, for the team only: General (name, description, status), Repositories (the GitHub defaults, moved from the Overview), Rules and Custom fields (moved from the Overview). The section is kept in the address, so a reload stays on it. A customer's contact has no Settings tab. Under the hood: a project can be archived (`archived_at`), and the database gains `project_github_repos`, `project_rules` and `project_rule_runs` for what follows; a linked pull request that is merged, closed or starts failing its checks is now noticed when it is synced, ready for rules to act on
- Automation rules, in Settings > Rules: when a task is added, moved, completed, reopened or assigned, when a due date is set or passes, when a comment is added, or when a linked pull request is merged, closed or fails its checks, the actions run (move, assign, unassign, due date, complete, reopen, label, comment, subtask, visibility). A project holds up to 50 rules, each with a run log; a chain of rule steps stops after five, so two rules cannot keep each other going. Agents get `list_rules`, `create_rule`, `update_rule` and `list_rule_runs`
- Board cards are quicker to use, as in Asana. A card ends in a round person button: dashed and empty until someone has the task, then their picture, and a click opens the list of people to hand it to or to clear it. An arrow at the other end opens the task (clicking the card still does too), and the column's last button now reads "Add task"
- GitHub integration. Paste an issue, pull request, branch or workflow run link, or `owner/repo#123` (`#123` alone once the project has a default repo), onto a task and read what GitHub says without leaving Taskmanager: the issue's title, state, labels, assignees and latest comments, the pull requests that name it with their review and check status, a branch's position against the default branch, a run's status. It is fetched on the server and cached, with a refresh button, and a rate limit or an outage is shown in words. A card carries a small badge such as `#45 merged, checks passing`. Every link is internal or visible to the customer, with a default per project under the project's Overview; a customer's contact sees only the customer-visible ones, in the app, on the board and through the agent tools. Agents get `link_github`, `unlink_github` and `get_task_github`, and `get_task` lists the links the key's person may see. On the server: `GITHUB_TOKEN` is optional, `GITHUB_ALLOWED_OWNERS` limits which owners may be linked (set it in production), and `POST /api/github/webhook` takes GitHub's signed deliveries (`GITHUB_WEBHOOK_SECRET`) to refresh links. The database gains `github_links`, `github_cache` and `project_github_settings`
- A task remembers who made it and keeps a log of what happened to it, as in Asana: created by, moved from one column to another, marked done or reopened, given to someone, renamed, a new start or due date, and a change of who it is visible to. The log sits in the task's Updates sheet between the comments, each line with who did it, whether it was an agent, and how long ago (hover for the exact time). Tasks from before the log begin with their creation date. The people who made a task are now told when it is finished, moved or commented on. The database gains `created_by` on `project_tasks` and a `task_activity` table
- The Inbox hears about more than assignments and comments: when someone marks a task done or reopens it, moves it to another column or changes its due date, its assignee and everyone who has commented on it get an item at the top of their Inbox, and the unread marker shows on the sidebar link whichever page they are on. Agents' `update_task` and `move_task` announce the same way
- Goals and portfolios update live. A teammate, an agent or another tab changing a goal or a portfolio shows on an open page without a reload, and so does work on a linked project: finishing its last task moves the goal's progress, adding one changes the portfolio's `done` count. The socket gains a `collection` event, staff-only like messages
- Goals and portfolios, as in Asana. A goal says what the work is for: a status, an owner, a due date, sub-goals, and progress that is typed in or read from the projects linked to it. A portfolio reads several projects side by side, with each one's health, how much is done and its latest status update. Both belong to the workspace (a team, or your own space) and only link its own projects. Agents get `list_goals`, `create_goal`, `update_goal`, `list_portfolios`, `create_portfolio` and `update_portfolio`; deleting is left to the app. The database gains `goals`, `goal_projects`, `portfolios` and `portfolio_projects`
- Web Push: an Inbox switch subscribes a browser or phone to notifications that arrive when Taskmanager is closed. Each notification is encrypted to the device and signed with the server's VAPID key (written against RFC 8291 and 8292, no new dependency); a device the push service reports gone is forgotten. Off until `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` are set; the NixOS module has `services.arnotes.push`. The database gains `push_subscriptions`
- Removed the notes feature entirely. `/note`, the sidebar notes panel, global notes search, and the five notes MCP tools (`list_notes`, `search_notes`, `get_note`, `create_note`, `update_note`, `delete_note`, `restore_note`) are gone, along with the `notes` database table and the `notes:read`/`notes:write` API key scopes. The app is boards and tasks only now
- Subtasks can nest to any depth, not just one level, and are reordered by dragging within their list or with Tab / Shift+Tab to indent and outdent, Asana-style. Typing a subtask's title and pressing Enter starts a new sibling right below it instead of just closing the field
- Renamed to Taskmanager wherever the name is shown: page titles, the logo, the installed app, sign-in emails, authenticator and passkey labels, the AI assistant's prompt, the MCP server's name and the docs. Install-level names stay as they were — `services.arnotes`, the `arnotes` package, database, user and Docker volumes — so an existing install upgrades in place. An MCP client that was added under the name `arnotes` keeps working; the setup page now suggests `taskmanager`
- Tasks have an assignee, a due date and a done mark, set from the task panel. Anyone in the organisation or a contact of the board's customer can be assigned. A card shows its assignee's avatar and its due date, red once the day has passed; without a due date it still reads the first `@date` in the description. The circle on a card marks it done without opening it
- Subtasks: a short list of tasks inside a task, added, ticked off and renamed in its panel. A card counts them (`1/2`); they are not cards themselves and stay out of search
- The database gains `assignee_id`, `due_on`, `completed_at` and `parent_task_id` on `project_tasks`
- Customers: an organisation can add customers, file projects under them, and invite their people with a single-use link. Contacts see the customer's boards in their personal workspace, can file tasks and post updates, and see only what is marked as visible to the customer
- Tasks and updates have a visibility. Tasks are visible to the customer by default and can be made **Internal**; updates start internal and are shared on purpose. Internal tasks are also left off public board links
- The first account on an instance is its admin and owns an organisation from the start; other accounts create organisations only once the admin allows it, under **Accounts on this instance**. On an existing instance, the oldest account becomes the admin at startup
- An invitation link lets its recipient create an account even where `ALLOW_SIGN_UP=false`
- The database gains `customers`, `customer_members` and `customer_invitations` tables, `customer_id` on `projects`, `visibility` on `project_tasks` and `task_comments`, and `is_instance_admin` and `can_create_organizations` on `user`
- Passkeys: add one under **Settings → Security**, then sign in with Touch ID, Windows Hello, a phone or a security key. On by default; no outside service needed
- Two-factor authentication with an authenticator app and one-time backup codes, set up under **Settings → Security**
- "Email me a code" sign-in, when an SMTP server is configured (`NUXT_PUBLIC_EMAIL_CODE_ENABLED` and `SMTP_*`). Accounts with two-factor on cannot use it
- Sign-in through your own OpenID Connect server — Authentik, Authelia, Keycloak and the like — with `NUXT_PUBLIC_OIDC_ENABLED` and `OIDC_*`
- The database gains `passkey` and `two_factor` tables and a `two_factor_enabled` column on `user`; the schema push on startup adds them
- `ALLOW_SIGN_UP=false` now closes sign-up through Discord, GitHub and Google as well. Before, it only stopped new email/password accounts, so a private instance with an OAuth button still let anyone in
- Sign in with Google: set `NUXT_PUBLIC_GOOGLE_ENABLED`, `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` to show the button, the same way Discord and GitHub are enabled
- The Arnai launcher is smaller and quieter, and the chat panel has softer borders and rounder corners
- The editor takes whatever is pasted into it: formatted text keeps its formatting, Markdown source becomes what it describes, a URL over a selection links it, code copied from VS Code lands in a code block of the right language, and checkbox lists from GitHub or Notion become task lists. Copying out puts Markdown on the plain-text side of the clipboard
- The selection toolbar gains **Turn into**, underline, six highlight colours and inline link editing (`⌘⇧K`); resting the caret in a link shows where it goes, with open, edit, copy and remove
- Every block has a handle: `+` adds a block below, the grip drags it — list items included, at any depth — and a click opens duplicate, copy as Markdown, move and delete. `⌥↑` / `⌥↓` move the current block or list item, `⌘⇧D` duplicates it
- `@` reads dates the way they are typed, in English or Dutch: `@fri`, `@in 3 days`, `@25 dec`, `@morgen om 14u`, `@2026-10-01`
- Global search is one keyboard-driven list: recent notes and tasks can be opened with the arrows before anything is typed, and `Tab` switches between All, Notes and Tasks
- Removed Archive, the memory assistant, along with its tables and its setting
- Projects: kanban boards beside the notes, with columns, drag-and-drop tasks, labels, rich-text descriptions written in the notes editor, and a running log of updates per task
- MCP server at `/api/mcp` letting Claude Code and other AI agents search, read, create, and edit notes
- Full board control over MCP: read boards and tasks, create and rename boards and columns, create, edit, move and delete tasks, and post task updates
- Live updates over a WebSocket at `/_ws`: a change made by an agent, a teammate or another tab appears without a reload, including in an open task panel
- Shareable boards: a read-only public link to a kanban board, optionally expiring, with no sidebar and no editing — the same deal a shared note gets
- Public pages follow the socket too, so a shared note or board updates while it is open and goes dark the moment sharing stops
- API keys scoped per workspace and per permission — notes and boards, read and write — managed under Settings, stored only as hashes and revocable at any time
- In-app setup guide at `/mcp` with the endpoint for your install, client configuration snippets, and a copyable agent skill
- Cards count their own checklists: a task list in a description shows as `2/4` on the card, with no subtask feature to manage
- Cards carry a due date read from the `@date` mentions already in their description, turning red once it is behind them
- Boards say how much is left rather than how much there has ever been: `8/47`, counting against whichever columns read as finished
- Labels autocomplete from the ones the board already uses, so a label stays one label
- The board can be walked from the keyboard: arrows move between cards, Enter opens one, `n` starts a card in the column you are on
- Long columns fold their tail behind one line, so a board that has been collecting finished work for months still opens quickly
- Boards have a trash: deleting a column or a task moves it there instead of destroying it, and **Show trashed** in the board menu draws the deleted columns and cards faded and in place, each with Restore and Delete permanently. The trash empties itself after 7 days
- Nothing an AI agent can reach deletes permanently any more. `delete_column` and `delete_task` move to the trash and are undone with the new `restore_column` and `restore_task`; a trashed row records whether it was the user, an MCP agent or the in-app assistant that deleted it
- Removed `delete_board` from the MCP server. Deleting a board takes its columns, tasks and updates with it, so it stays in the app behind a confirmation where an agent cannot reach it
- Restoring a column brings its tasks back: the ones handed to a neighbour when it was deleted return, unless they have since been filed somewhere on purpose
- Columns and task labels can be given a colour of their own, from the same palette as the accent in Settings: a column through **Change color** in its menu, a label by right-clicking it anywhere it appears. Both fall back to the colour derived from their name until one is set, and agents can colour a column through `update_column`
- Task updates take Markdown, deliberately a narrow one: bold, italic, inline code, strike, highlight and links, and nothing that opens a block. The update box is the editor itself with none of an editor's furniture — no toolbar, no border — so `**shipped**` turns bold as it is typed
- Updates posted over MCP are signed with the API key that posted them and marked as an agent's, instead of appearing under the key owner's name
- Global search takes a half-typed tag: `#sani` filters by every tag it could still complete to, and a tag now narrows tasks and boards as well as notes, matching a task's labels or its board's name
- Global search can be pointed at one half of the workspace with an All / Notes / Tasks switch, and the row of tag chips is gone — `#tag` in the box does the same job
- Task updates are for people again: `add_task_update` is gone from the MCP server, so the log holds what the team writes — on staging, customer feedback, needs more work — and not an agent's summary of its own session. Agents can still read the thread through `get_task`
- A task's updates open in a sheet of their own from a button in the task panel's header, instead of taking the bottom of the panel away from the description
- The board menu no longer carries a dot when something is in the trash
- Your own task updates can be edited in place or deleted from the update's menu; an edited update says so
- Opening a board changes the page on the click: the board being left is no longer drawn again under the new one, a board seen before comes back from memory while it refreshes, the first cards of each column paint before the rest, and label chips build their right-click menu only when it is used
- Fixed: dragging a card while a label filter was on could give two cards the same position, leaving them to swap places on their own
- Fixed: deleting a board's last column destroyed its tasks while the confirmation promised they would move
- Fixed: a card picked up on a touch screen no longer swallows the scroll — a card drags after a short hold
- Fixed: the editor's divider did nothing. It was offered in the `/` menu but the extension behind it was switched off, so the entry was dead; it now works from there, from a new toolbar button, and by typing `---`

## 0.1.0 - 2026-07-28

Initial open-source release.

- Self-hosted rich-text notes with inline tags, search, attachments, sharing, and an installable PWA
- Email/password authentication with optional Discord OAuth
- Optional per-user OpenRouter integration and AI usage history
- One-command Docker Compose deployment with PostgreSQL, health checks, automatic Drizzle schema setup, and persistent storage
- Standalone GitHub Pages marketing site
